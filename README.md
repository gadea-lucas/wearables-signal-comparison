# Wearable biosignal placement comparison pipeline

This repository contains the reproducible preprocessing and analysis pipeline used to investigate the effect of sensor placement on physiological signals recorded with **Shimmer3 GSR+** and **EmotiBit** wearable devices.

The analyses focus on **electrodermal activity (EDA/GSR)** and **PPG-derived heart rate (HR)** acquired at different body placements.

EmotiBit recordings were obtained at the **volar** and **dorsal** sides of the wrist. Shimmer3 GSR+ recordings were acquired using two configurations:

- **wrist configuration**, with the GSR electrodes on the volar side of the wrist and the PPG sensor on the dorsal side;
- **finger configuration**, corresponding to the finger placement used for the device.

The repository includes:

- physiological signal preprocessing;
- outlier detection and filtering;
- temporal alignment;
- placement-based correlation analysis;
- temporal physiological-response visualization;
- participant-level bootstrap analysis;
- illustrative Random Forest classification using time-series features.

> Raw recordings are not distributed through GitHub. The exact dataset associated with this code release is publicly available on Zenodo: 
>
> [![DOI](https://img.shields.io/badge/DOI-10.5281/zenodo.22655618-blue)](https://doi.org/10.5281/zenodo.22655618)

## 📁 Dataset

First, download the dataset from Zenodo. Then, after extracting the archive, place the `data/` directory at the root of this repository.

The expected structure is:

```text
data/
├── emotibit_dorsal/
│   └── <participant_id>/
│       ├── raw/
│       └── parsed/
│
├── emotibit_volar/
│   └── <participant_id>/
│       ├── raw/
│       └── parsed/
│
├── shimmer_wrist/
│   └── <participant_id>.csv
│
├── shimmer_fingers/
│   └── <participant_id>.csv
│
└── Stamps/
    └── <participant_id>.txt
```

### EmotiBit

The `emotibit_dorsal/` and `emotibit_volar/` directories contain recordings acquired at the dorsal and volar sides of the wrist, respectively.

Each participant directory contains:

- `raw/` contains the original EmotiBit export (`.csv` + `_info.json`)
- `parsed/`[^1]  contains one file per channel (AX, AY, AZ, GX, HR, PG, etc.)
- Includes synchronization files: `timeSyncMap.csv`, `timesyncs.csv`

[^1]: EmotiBit recordings follow the structure generated by the official [EmotiBit DataParser tool](https://github.com/EmotiBit/EmotiBit_Docs/blob/master/Working_with_emotibit_data.md#emotibit-dataparser).


### Shimmer3 GSR+

The Shimmer3 GSR+ recordings are provided as one CSV file per participant.

`shimmer_wrist/` corresponds to the wrist configuration. In this configuration, the GSR electrodes were located on the volar side of the wrist, whereas the PPG sensor was located on the dorsal side.

`shimmer_fingers/` corresponds to the finger placement.

### Experimental timestamps

`Stamps/` contains one event-marker file per participant. These timestamps identify the experimental intervals and are used to align and segment the physiological recordings.

Participant identifiers are anonymized and consistent across the corresponding device and placement folders.

# 📊 Analysis workflow

## 01. Physiological signal preprocessing

Notebook:

```text
01_preprocessing.ipynb
```

This notebook loads the recordings from `data/` and applies the physiological signal-processing pipeline used in the associated manuscript.

The pipeline includes:

- signal loading and synchronization;
- outlier detection;
- signal-specific filtering;
- resampling where required;
- extraction of the physiological signals used in the analyses;
- generation of a common processed-data structure for all device placements.

The main output is:

```text
processed_data/
└── processed_data.pickle
```

This file is used by all subsequent notebooks.

---

## 02. Comparison visualization

Notebook:

```text
02_visualisation.ipynb
```

This notebook performs the placement-focused descriptive and correlation analyses.

It includes:

- Pearson correlation analysis between device-placement pairs;
- analysis of individual experimental intervals;
- generation of the corresponding correlation tables;
- visualization of the physiological response throughout the experimental protocol.

The physiological-behaviour figure combines all four placements in a single figure:

- grey curves represent individual participants;
- the red curve represents the group mean;
- the red band represents the pointwise 95% bootstrap confidence interval;
- colored backgrounds identify the experimental conditions.

EDA/GSR is analyzed using the `IQR → Gaussian` processing branch, whereas PPG-derived HR uses the `IQR → Butterworth` branch.

Main outputs are written under:

```text
results/
├── scatter/
├── n_means/
└── table/
```

---

## 03. Whole-session participant bootstrap

Notebook:

```text
03_bootstrap_analysis.ipynb
```

This notebook provides participant-level uncertainty estimates for the whole-session correlation analysis.

For each physiological signal and device-placement comparison:

1. the complete experimental interval is selected;
2. the two signals are temporally aligned for each participant;
3. one Pearson correlation coefficient is calculated per participant;
4. participant correlations are Fisher-z transformed;
5. participants are resampled with replacement;
6. the bootstrap estimate is transformed back to the correlation scale;
7. the group correlation and its 95% percentile bootstrap confidence interval are reported.

The bootstrap therefore operates at the **participant level**, rather than treating individual time samples as independent observations.

Outputs are written to:

```text
results/bootstrap/
```

including participant-level correlations, bootstrap estimates, and manuscript summary tables.

---

## 04. Illustrative Random Forest classification

Notebook:

```text
04_classification.ipynb
```

This notebook provides an illustrative classification analysis to assess whether the physiological signals contain sufficient information to discriminate changes associated with the experimental conditions.

The analysis uses both:

- EDA/GSR;
- PPG-derived HR.

For each participant and device placement:

1. each signal is standardized relative to the participant-specific baseline;
2. the experimental intervals are divided into **8-second windows**;
3. consecutive windows use **50% overlap**, corresponding to a **4-second step**;
4. time-series features are extracted independently from EDA/GSR and HR using `tsfresh` with `EfficientFCParameters`;
5. features from both physiological signals are combined;
6. a Random Forest classifier with **500 trees** is trained;
7. evaluation is performed using **leave-one-subject-out cross-validation**.

All windows from the held-out participant remain exclusively in the test set, preventing participant-level data leakage between training and test data.

The four classification conditions are:

- Relax;
- Squat;
- Video 1;
- Video 2.

The main outputs include normalized confusion matrices and classification metrics:

```text
processed_data/
└── classification_features/
    ├── emotibit_volar_features_w8_overlap50.csv
    ├── emotibit_dorsal_features_w8_overlap50.csv
    ├── shimmer_wrist_features_w8_overlap50.csv
    └── shimmer_fingers_features_w8_overlap50.csv

results/
└── classification/
    ├── confusion_matrices_rf.pdf
    ├── confusion_matrices_rf.png
    ├── summary_metrics.csv
    ├── all_predictions.csv
    ├── experiment_config.json
    ├── <device>_fold_metrics.csv
    ├── <device>_confusion_counts.csv
    └── <device>_confusion_normalized.csv
```

The feature CSV files are intermediate cached outputs and can be regenerated directly from `processed_data/processed_data.pickle`.

# ▶ Reproducing the complete analysis

1. Download the dataset from Zenodo.
2. Extract the `data/` directory into the repository root.
3. Install the dependencies:

```bash
pip install -r requirements.txt
```

4. Execute:

```text
01_preprocessing.ipynb
```

5. After preprocessing has completed, execute:

```text
02_visualisation.ipynb
03_bootstrap_analysis.ipynb
04_classification.ipynb
```

The last three notebooks all use:

```text
processed_data/processed_data.pickle
```

and do not depend on one another.

The `tsfresh` feature-extraction stage in `04_classification.ipynb` is computationally more demanding than the other analyses. Extracted feature tables are cached so that subsequent executions can reuse them.
